# 非机动车与行人运动优化

实现包含独立对照试验和原七组全程更新流程。`a2s.replay` 保留记录位姿基线；正式运动优化版由 `a2s.motion_release` 录制、检查并发布。实际交付状态以 `outputs/motion_update_audit.json` 和各组实机记录为准。

## 已实现

- `motion.py`：根据重建路网坐标中的轨迹位置计算速度和方向，处理 ±180° 朝向和停车；两轮目标使用前视点转向与 PI 速度跟踪，行人使用轨迹速度前馈和位置误差反馈。
- `motion_pilot.py`：在已导入的 FBX/XODR 地图中运行 CARLA 0.9.15，以 30 Hz 同步控制并录制指定目标。两轮目标使用 `VehicleControl` 驱动物理车辆，行人使用原生 `WalkerControl` 和动画。其他目标仍沿记录位姿回放。
- `motion_audit.py`：筛查原七组的 62 个骑行、行人及语义相近目标，识别不适合两轮控制的三轮车、篷车和清扫车替代模型。不会修改原始轨迹或事故时间。
- `motion_review.py`：合成相同时间、相同观察机位的优化前后视频，包含俯视参考、速度、位置误差和偏航角曲线，并生成独立浏览页面。

## 重现方法

先启动 CARLA 0.9.15；客户端也必须为 0.9.15。默认 Python 里如果是旧版 CARLA，不要直接运行。可把匹配当前 Python 的官方 wheel 安装到项目隔离目录：

```powershell
python -m pip install --no-deps --target runtime\motion_python <CARLA-0.9.15-wheel路径>
python -m unittest discover -s tests -p test_motion.py -v
python -m a2s.motion_audit
.\scripts\run_motion_pilot.ps1 -Scene 024388 -Mode optimized -Tag my_review
.\scripts\run_motion_pilot.ps1 -Scene 024388 -Mode baseline -Tag my_review
python -m a2s.motion_review --scene 024388 --tag my_review
# 三组对照均生成后检查实际视频与网页拖动播放：
python tools\check_motion_review.py --url http://127.0.0.1:8765/motion_review/
```

另外两组使用 `0508656` 和 `019742`。已有试验记录禁止覆盖，重复试验使用新 Tag。

逐帧证据写到 `outputs/<scene>/validation/motion_pilot/<tag>/<mode>/`，浏览材料写到 `outputs/motion_review/`。现有网页服务可直接打开 `/motion_review/`。该目录在 Git 忽略范围内。

## 独立对照试验的验证解释

- 每个相机帧和遥测快照必须来自同一 CARLA frame；优化前后场景、参考轨迹哈希、目标、时间范围、频率必须一致。
- 优化目标只在初始化时设置位姿与初速度，正式采样期间不瞬移纠偏。两轮车辆先预热引擎、变速箱和悬架，再设置测得的初始状态；这属于仿真初始化，不是原始事故的起步过程。
- 试验跟踪阈值预先设为位置误差 P95 ≤ 0.5 m、最大 ≤ 1 m、偏航误差 P95 ≤ 10°。它们是本次工程验收目标，不是传感器测量精度。原有逐帧位姿回放的厘米级校验不适用于物理跟踪。
- 行人读取组件坐标系中的腿、脚骨骼变化，避免把整个人的位置移动误认为腿在运动。原生动画是否自然、脚底接触和停止效果仍需要视频检查。
- 油门、制动、转向来自有界控制，实际运动由 CARLA 求解。本版尚未标定真实电动车的质量、轮胎、动力和骑行者参数；Vespa 替代模型不能被称为实车动力学模型。
- 轨迹筛查中速度、加速度、横向加速度超限会被报告，不会偷偷降速或改变事故时刻。需要结合原视频决定后续修正。
- `success` 表示录制完成；`tracking_accepted` 单独表示跟踪阈值通过；`gait_detected` 表示骨骼运动被检测到。三者不可混用。碰撞动力学仍明确标记未验证。

## 七组全程更新

`motion_full.py` 在 30 Hz 同步控制中运行全部适用目标，以 10 fps 保存主车前视和跟随画面。`motion_runtime.py` 管理原生步态、转向、油门和制动；参考轨迹无法由当前替代模型及时跟踪时，启用明示的水平位置约束、朝向/地面稳定和速度辅助。水平约束计数与最大单步位移、速度辅助次数、位置误差、运动中偏航误差以及脚部骨骼范围分别记录。它与前三组试验的“无运行中位置纠偏”模式不同。

正常水平修正单步最多 0.18 m；偏差大于 1 m 时重新约束至参考附近，并记录实际修正量。此设置优先保留估计事故时序，不能用于宣称自由碰撞动力学精度。速度超过 10 m/s 时使用有界参考速度积分辅助，避免原生变速箱反复降速导致持续落后；参考速度命令按加速 4 m/s²、减速 6 m/s² 限制变化，这不代表实际测得加速度始终满足相同边界。

全程验收检查每目标位置误差 P95 ≤ 0.5 m、最大 ≤ 1 m、运动中偏航误差 P95 ≤ 15°。行走目标的两个脚部组件坐标变化范围均须超过 0.03 m，以排除只有整个人平移的情况；此检查不等于步态与原视频逐帧匹配。静止行人使用零速度控制，不要求走路动作。

原七组共筛查 62 个相关目标，排除语义或模型不匹配的三轮车、篷车和清扫车后，对适用目标启用原生运动。其余车辆（包括 ego）保持记录位姿校验；不把所有目标的“厘米级姿态执行误差”套用到原生运动上。

`configs/motion_overrides.json` 明确记录逐目标例外：019742 的背景 `crossing_scooter` 估计轨迹穿过重建围挡/中央隔离设施，原生物理会发生朝向翻转，因此保留该目标原有位置、偏航和时序。它不计入原生物理跟踪通过的目标；事故相关逆行骑行目标仍使用新控制。

016955 的事故相关 `cross_scooter_b` 在约 74 秒后的离场轨迹与重建人行道/路侧几何冲突，亦明确保留记录位置、偏航和时序，不能算作原生物理跟踪通过。另一辆横穿骑行目标及本场行人使用新控制。两条静态冲突例外均写入配置和逐场实机记录。

为避免 CARLA 0.9.15 在目标退出摩擦区域时访问已释放的轮胎状态，运动版不创建全局摩擦触发器，改为对原生车辆直接设置轮胎摩擦参数。生命周期结束的目标移出画面并停止物理，录制结束后统一清理；不会在视频中继续保留退场目标。

`motion_movie.py` 保持原汇报排版，俯视图中适用目标使用与相机帧对应的实际 CARLA 位置。视频采用随时长调整的码率上限，符合 GitHub 单文件限制。

```powershell
$env:PYTHONPATH=(Resolve-Path runtime\motion_python).Path
python -m a2s.motion_release run
python -m a2s.motion_release audit
python -m a2s.motion_release promote
python tools/export_pages.py
python tools/check_pages.py
```

独立工作目录为 `work/motion_release`，旧正式结果保存到该目录下的 `previous_release`。七组均通过运行、视频、帧同步、位置/偏航及完整覆盖检查后，才执行正式替换。下一次更新可用 `--stage work/motion_release_新版本`。

2026-09-14 全程运行结果覆盖 181 个登记实体：36 个骑行目标与 18 个行人使用新控制，6 个不匹配替代模型和上述 2 条静态冲突轨迹保留记录位姿。每路相机共 9,514 帧。54 个新控制目标均通过工程跟踪阈值，最大位置误差为 0.932 m 以内，各目标运动中偏航误差 P95 的最大值为 11.20° 以内。18 个行人中 17 个存在行走片段，左右脚组件坐标变化范围均超过 0.16 m；另一个保持静止。这些数字衡量对估计轨迹的执行与动画变化，不代表真实事故重建精度或自由碰撞动力学。
